Paystack Subscription & Recurring Billing Architecture

Automating SaaS Subscriptions, Tokenization, & Retries
By Fort Engineering Team | August 15, 2026 | 9 Min Read

Building a successful Software-as-a-Service (SaaS) or subscription membership platform depends heavily on friction-free, automated recurring billing. Rather than forcing users to manually re-enter payment details every billing cycle, modern applications store secure reusable payment tokens and utilize automated plan schedulers.

Paystack provides a comprehensive, developer-first subscription ecosystem. This guide details how the Fort Engineering team integrates Paystack Subscription Plans, card tokenization, recurring authorization charges, and automated dunning management for SaaS platforms.

1. Core Mechanics of Paystack Subscriptions

There are two principal ways to manage recurring billing with Paystack:

  • Paystack-Managed Plans: You create a Plan on Paystack with a specified amount and interval (e.g., Monthly Pro Plan = 10,000 NGN). When a user subscribes, Paystack automatically re-charges their card on the scheduled renewal date without server intervention.
  • Custom Charge Authorizations (Tokenization): When a user completes an initial transaction, Paystack returns a re-usable authorization_code in the webhook payload. Your application stores this code securely and triggers tokenized charges via API whenever custom billing logic dictates (e.g., metered usage or custom invoice schedules).

2. Programmatically Creating Subscription Plans

To initialize Paystack-Managed subscriptions, you must first define subscription plans via the REST API or Dashboard:

// Creating a Monthly SaaS Plan via Paystack API
const axios = require('axios');

async function createSaaSPlan() {
    const response = await axios.post('https://api.paystack.co/plan', {
        name: "Pro Monthly Membership",
        interval: "monthly",
        amount: 1500000, // 15,000 NGN in kobo
        currency: "NGN",
        description: "Unlocks premium cloud design tools and unlimited storage."
    }, {
        headers: { Authorization: `Bearer ${process.env.PAYSTACK_SECRET_KEY}` }
    });

    return response.data.data.plan_code; // e.g., 'PLN_xxxxxxxxx'
}

3. Subscribing Users & Capturing Payment Tokens

When a user initiates a subscription signup, pass the generated plan_code in your checkout setup. Once completed, subscribe webhooks broadcast the new subscription details along with the user's re-usable card authorization token.

// Node.js Webhook Handler for Subscription Events
app.post('/api/webhooks/paystack-subscription', express.json(), async (req, res) => {
    const event = req.body;

    // Handle initial successful subscription charge
    if (event.event === 'subscription.create') {
        const { subscription_code, email_token, customer, plan } = event.data;

        await db.userSubscriptions.create({
            data: {
                userId: customer.email,
                subscriptionCode: subscription_code,
                emailToken: email_token,
                planCode: plan.plan_code,
                status: 'ACTIVE',
                nextPaymentDate: new Date(event.data.next_payment_date)
            }
        });
    }

    // Handle recurring renewal charges
    if (event.event === 'charge.success' && event.data.plan) {
        await db.userSubscriptions.update({
            where: { subscriptionCode: event.data.subscription.subscription_code },
            data: { status: 'ACTIVE', lastRenewal: new Date() }
        });
    }

    res.sendStatus(200);
});

4. Handling Payment Failures & Dunning Management

Card expirations, insufficient funds, or temporary bank downtime can cause recurring payment renewals to fail. Paystack automatically implements smart retries (retrying failed cards over several days). Your application must listen for invoice.payment_failed webhooks to implement proper dunning flows:

  1. Grace Period Status: On the first failed attempt, update subscription status to PAST_DUE while maintaining access for 3 days.
  2. Automated User Notification: Send an automated email prompting the user to update their payment method via Paystack's Update Payment Link API.
  3. Account Suspension: If retries fail after the dunning window closes, consume the subscription.disable event to lock premium features until re-activation.
